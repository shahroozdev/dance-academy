# 5. Parent Notifications & WhatsApp Automation

## 5.1 Message content & grouping (§9)

Once a month's bills are generated, the system builds one message **per family** (not per student)
whenever a family has 2+ billed students, combining every student's Final Amount Due into a single
message — matching the doc's example exactly:

```
Hi Anu,
September dance fees:
Nia – $144.40
Leia – $76.00
Total family amount due: $220.40
Please send the payment when convenient. Thank you!
```

Data used to build it: Parent Name (`Family.parentGuardianName`), each Student Name + their
`finalAmountDue`, `month`, the family total (sum of the family's bills for that month), and overall
due/paid status. Message text is generated by a pure function (`buildFamilyMessage`), unit tested
the same way as the billing engine — the admin never hand-types a number into a message.

## 5.2 Delivery channel decision

WhatsApp Business messaging to a customer **outside** an open 24-hour conversation window (i.e.,
a studio-initiated monthly fee reminder, which is exactly this use case) legally/technically
requires sending a **pre-approved Message Template** through Meta's WhatsApp Business Platform —
this applies no matter which provider is used underneath, because it's a WhatsApp policy, not a
vendor limitation.

| Option | Setup cost | Per-message cost (~50 students / ~30 families) | Notes |
|---|---|---|---|
| **Meta WhatsApp Cloud API (direct, recommended)** | $0 — free developer account + one verified phone number via Meta Business Manager | Utility-category template messages: roughly **$0.005–$0.02 per conversation** depending on recipient country (US rates currently ~$0.0146/utility conversation). One conversation covers all messages to that recipient within a 24h window, so a monthly billing message + a later payment-reminder message for the same family in the same window count as one conversation. At ~30 families/month → **roughly $0.15–$0.60/month**, plus occasional reminder conversations. | No middleman markup, no monthly platform fee. Requires Meta Business verification (free, one-time, can take a few days) and one approved Utility template. |
| Twilio WhatsApp API | Twilio phone number ~$1–2/mo | Same Meta per-conversation fee **plus** Twilio's per-message markup (~$0.005) | Easier developer experience/dashboard, but strictly more expensive than going direct for no functional benefit at this scale. |
| Gupshup / 360dialog (BSPs) | Often $0 setup, some require a monthly platform fee (~$10–50/mo depending on plan) | Meta's per-conversation fee, sometimes bundled | Useful if the studio ever wants a shared team inbox; not justified for one admin sending ~30 messages/month. |
| **Zero-cost fallback (MVP bridge while template approval is pending)** | $0 | $0 | The system always generates the message text and shows a **"Copy Message"** button per family (and a `wa.me/<phone>?text=<encoded message>` deep link) so the admin can send manually from their own WhatsApp while Meta's business/template approval is in progress. This satisfies the requirement end-to-end on day one without waiting on Meta's review queue. |

**Recommendation**: integrate the **Meta WhatsApp Cloud API directly** (no BSP middleman). Expected
recurring cost at current scale: **under $1/month**, likely $0 some months if usage stays inside
any promotional/free allotment Meta offers at the time. This must be re-confirmed against Meta's
current published pricing before go-live, since per-conversation rates are set by Meta and can
change — the admin settings page (§3.14) will surface the last-known rate and a link to Meta's
pricing page for the owner's own verification, per the doc's explicit requirement to disclose exact
costs before implementing anything paid.

## 5.3 Flow implementation

```
Monthly bills finalized (admin reviews the /admin/billing workspace, adjustments entered)
        │
        ▼
Admin clicks "Send Notifications" (single family or bulk-for-month)
        │
        ▼
buildFamilyMessage(familyId, month)  → personalized text using each bill's finalAmountDue
        │
        ▼
Family.phone retrieved, normalized to E.164 (+1XXXXXXXXXX)
        │
        ▼
POST to Meta Graph API: /{PHONE_NUMBER_ID}/messages
  { messaging_product: "whatsapp", to, type: "template", template: { name: "monthly_fee_notice", ... } }
        │
        ├─ success → NotificationLog.status = SENT, sentAt = now, providerMessageId stored
        │            MonthlyStudentBilling.notificationStatus = SENT for each included bill
        │
        └─ failure → NotificationLog.status = FAILED, errorMessage stored, shown in /admin/notifications
                      for manual retry or fallback to "Copy Message"
        │
        ▼
Meta delivery-status webhook (POST /api/webhooks/whatsapp) updates NotificationLog with
delivered/read status when available (best-effort, not required for the core flow to work)
```

## 5.4 Reminder automation (§9.1, "later reminder automation should be possible")

A separate scheduled job, `POST /api/cron/send-payment-reminders`, runs daily and finds bills where
`status IN (UNPAID, PARTIAL)` and `month`'s configured due date has passed by N days (configurable
in Settings, default 7). It reuses the same `buildFamilyMessage`/send pipeline with a distinct
`payment_reminder` template (separate Meta template approval, since template content changes
require re-approval), and records reminders in the same `NotificationLog` so the admin can see a
full history of every message sent to a family, not just the original notice.

## 5.5 Message template approval note

Meta requires Utility-category templates to be submitted for review before first use (typically
approved within minutes to ~24 hours). Two templates are needed at launch:

1. `monthly_fee_notice` — the original per-month billing message.
2. `payment_reminder` — the past-due nudge.

Both are drafted in [03-routes-and-pages.md §3.14](./03-routes-and-pages.md#314-settings-adminsettings)'s
Settings page for the owner to review before submission, since Meta will reject templates that look
like marketing rather than a factual utility notice (no promotional language, no incentives).
